はじめる・上げる

お店を作る、EC-CUBE を上げる、この環境を新しくする。どれを、どこで、どの順に打つかを図にしました。

やりたいことから選ぶ

「上げる」「更新する」と言っても、相手は 3 つあります。どれを上げたいのかが分かれば、やることは決まっています。

お店のソフト

EC-CUBE

4.3.2 のような番号

商品・カート・管理画面。お店そのもの。脆弱性の案内が来るのは、たいていここ。

EC-CUBE を動かす台と道具

eccube-docker（この環境）

v1.0.19 のような番号（v 付き）

bin/ のコマンドや、サーバーの組み立て。このページで配っているもの。

EC-CUBE を動かす言語

PHP

8.3 のような番号

EC-CUBE の下で動いているもの。パッチは毎朝、配布イメージに入ります。

何がしたいですか？

お店をこれから作るまだ何も無い → A新規作成 EC-CUBE の脆弱性の案内が来た／EC-CUBE の新しい版が出た「EC-CUBE 4.3.2 をリリースしました」など、v の付かない番号 → BEC-CUBE のバージョンアップ eccube-docker の新しい版が出た「v1.0.19」など、v の付く番号。月に 1 回くらい確かめる → C環境のアップデート
PHP の脆弱性の案内が来た「PHP 8.3.37 を公開」など → –いつもの bin/deploy.sh だけ
配布イメージに翌朝入るので、反映を打てば届きます。A〜C は要りません。8.2 → 8.3 のように番号を変えるときは、バージョンを変えるのは、それぞれ 1 コマンドの表。
自分で直したところを、お店に出したいCSS・テンプレート・プラグインなど → –いつもの bin/deploy.sh
毎日の手順は はじめての人のための手引き。
A

新規作成

パソコンで動かしてから、サーバーに出します。サーバーには何も入れに行きません。全部パソコンから打ちます。

時間: パソコンで動くまで 5 分、公開まで 30 分ほど。

git clone はしません。clone だと送り先が配布元のままで、あなたのコードを保存する場所がありません。中身だけもらって、自分専用の非公開リポジトリにします。

  1. パソコン中身をもらう

    curl -fsSL https://github.com/kurozumi/eccube-docker/releases/latest/download/eccube-docker.tar.gz | tar -xz
mv eccube-docker-* myshop && cd myshop

  2. パソコン自分の非公開リポジトリにする

    git init -b main && git add -A && git commit -m "eccube-docker から開始"
gh repo create myshop --private --source=. --push

  3. パソコン動かしてみる

    bin/init.sh --image=ghcr.io/kurozumi/eccube-docker/ec-cube:4.3-php8.3

    数十秒で終わり、URL（http://localhost:8080/）と管理画面のログイン情報が出ます。4.3 が EC-CUBE の版、php8.3 が PHP の版です。

  4. サーバーサーバーを整える（パソコンから打つ）

    bin/bootstrap-server.sh user@サーバー /srv/myshop

    Docker を入れ、お店のファイルを送ります。サーバーは SSH で入れるようにしておくだけ。

  5. サーバーメールと公開の設定（パソコンから打つ）

    bin/setup.sh mail   --remote=user@サーバー:/srv/myshop
bin/setup.sh tunnel --remote=user@サーバー:/srv/myshop

    質問に答えるだけ。メールは 1 通試してから、公開は Cloudflare につながるか試してから書きます。

  6. サーバー公開して、毎日のバックアップを入れる

    bin/publish.sh      --remote=user@サーバー:/srv/myshop
bin/setup.sh backup --remote=user@サーバー:/srv/myshop

  7. ブラウザお店を開いて確かめる

    これ以降、直したものを出すのは bin/deploy.sh --remote=user@サーバー:/srv/myshop だけです。詳しくは 導入手順。

B

EC-CUBE のバージョンアップ

例: EC-CUBE 4.3.1 → 4.3.2。パソコンで試してから、サーバーで上げます。

時間: お店が止まるのは数分。

そのまま残るもの: 受注・会員・商品・画像、あなたが直したテンプレートや CSS、プラグイン。
止まったら: たいていはお店に触る前に止まり、そのまま動き続けます。DB を変える途中で止まったときはメンテナンス表示のまま止まるので、失敗したときの表に沿って戻します（バックアップは自動で取ってあります）。

  1. どの番号が変わるかを見る

    3 つ目だけ（4.3.1 → 4.3.2）パッチ。このまま次へ。
    2 つ目（4.3 → 4.4）プラグインの作り直しが要ります。ひとりで進めず、制作者に相談してください（バージョンアップ）。

  2. パソコン先に環境を新しくする

    下の C を済ませます。古い道具で新しい EC-CUBE を扱わないためです。

  3. パソコンパソコンで上げて、試す

    bin/upgrade.sh ~4.3.0

    ~4.3.0 は「4.3 の中で一番新しい版」。「取得したイメージの EC-CUBE: 4.3.2」と出たら、案内にあった版（またはそれより新しい版）かを見ます。古ければ n で止め、翌朝の配布イメージを待ちます。合っていれば番号を控えて y。終わったら http://localhost:8080/ で、トップ・商品・カート・管理画面を開いてみます。

    できれば本番のデータで試します。本番にだけ残っているプラグインの列なども、そこで見つかります。いつもの手元の環境に戻すと作業中のデータが上書きされるので、別のフォルダに検証用を作って本番のバックアップを戻します（ステージングで予行演習）。

  4. サーバーお客さんに告知してから、サーバーで上げる

    ssh user@サーバー
cd /srv/myshop
bin/upgrade.sh ~4.3.0 --prod

    --prod を必ず付けます。出てきた EC-CUBE の番号がパソコンで試したものと同じかを見てから y（違えば n で止め、パソコンで試し直す）。自動でバックアップを取り、新しい EC-CUBE でプラグインが動くかを、お店に触る前に確かめます。

  5. ブラウザ目で確かめる

    トップ・商品詳細・カートに入れる・管理画面のログイン・受注一覧。おかしければ bin/plugin.sh doctor。

C

環境のアップデート

例: eccube-docker v1.0.18 → v1.0.19。パソコンで取り込み、いつもの deploy でサーバーへ。サーバーで直接は取り込みません。

時間: 5 分ほど。お店はほとんど止まりません。

触らないもの: EC-CUBE の版、お店のデータ、あなたが直したもの、.env。
新しくなるもの: bin/ のコマンド、サーバーの組み立て、文書。

  1. パソコン何が変わるかを見る

    bin/self-update.sh --check

    まだ何も書き換えません。リリースノートの「まずやること」も読みます。版によっては、ひと手間あります。

  2. パソコン取り込む

    bin/self-update.sh

    配布元が変えたファイルだけを差し替えます。あなたが手を入れたファイルとぶつかるときは、上書きせずに止まって知らせます。

  3. パソコン控えを送る

    git add -A && git commit -m "eccube-docker v1.0.19" && git push

  4. サーバーいつもどおり反映する（パソコンから打つ）

    bin/deploy.sh --remote=user@サーバー:/srv/myshop

  5. ブラウザお店を開いて確かめる

対応する EC-CUBE

配布イメージを使うと、手元でビルドせずに数十秒で立ち上がります（bin/init.sh --image=… か .env の ECCUBE_IMAGE）。PHP はタグで選びます: 4.3-php8.3 のように書くとその PHP、-php を省くと系列の既定。

系列イメージ（本番はこれ）選べる PHP備考
4.3ghcr.io/kurozumi/eccube-docker/ec-cube:4.38.1† / 8.2 / 8.3推奨
4.2ghcr.io/kurozumi/eccube-docker/ec-cube:4.28.1† / 8.2
4.4ghcr.io/kurozumi/eccube-docker/ec-cube:4.48.2 / 8.3 / 8.4 / 8.5上流の開発ブランチから焼いている。同じものを立てたいなら日付タグで固定

公式の PHP イメージが作り直されたら、翌朝その組だけ焼き直します（月曜は全部）。PHP のセキュリティパッチは公開の翌日に入り、OS のパッチも遅くとも 1 週間で入ります。受け取るのは bin/deploy.sh（nginx・Redis・DB などのミドルウェアも一緒に引き直す）。ミドルウェアの脆弱性・保守期限・Docker の設定も毎日点検しています。 †PHP 8.1 は 2025 年 12 月で終了しています。OS のパッチは入りますが PHP 自体の修正はもう出ないので、8.1 でしか動かないプラグインが無ければ 8.2 以上を。太字は -php 無しの既定。PHP を選ぶなら 4.4-php8.5 のように書く。同じものを何度も立てたい人は日付タグ 4.3-20260907、リリース時点なら 4.3-__TAG__。

DB は MariaDB / MySQL（既定）か PostgreSQL。版は .env の MARIADB_VERSION / PG_VERSION。.env の DB_ENGINE で選び、バックアップも引っ越しも同じコマンドで通ります。手元の DB でも、クラウドのマネージド DB でも。
